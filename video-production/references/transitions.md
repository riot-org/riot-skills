# 转场手册

转场是视频里最容易做坏的部分。motion.js 已经把每种转场的位移、透明度、遮罩算好了，你只需要做对三件事：**选对转场**、**让新场景的元素在对的时刻出现**、**用 --check 验证**。

## 时间是怎么算的

```
场景 A（dur = 4.9）                      场景 B（dur = 4.9）
|───────────────────────────|─────────────────────────────|
0                          4.9                           9.8
                       ↑    ↑    ↑
              转场开始  分界点  转场结束
         (4.9 - d/2)  (4.9)  (4.9 + d/2)      d = 转场时长
```

- **分界点** = 前面所有场景时长之和。转场以分界点为中心，前后各占一半。
- 在场景 B 的 `render(lt, s)` 里：`lt = 0` 是分界点，`s.inStart = -d/2` 是转场开始，`s.outStart` 是 B 离开时的转场开始。
- 转场期间 A 和 B 同时在画面上，B 在上层。
- 时长写成小节的整数倍（`bars`）时，分界点正好落在音乐强拍上，转场的视觉中心和鼓点重合。

## 怎么写

```js
{ id: "s-b", dur: 4.9, transition: "crossfade" }
{ id: "s-b", dur: 4.9, transition: "push-left" }                      // 类型-方向
{ id: "s-b", dur: 4.9, transition: { type: "push", dir: "up", dur: 0.8 } }
{ id: "s-b", dur: 4.9, transition: { type: "fadeThrough", color: "#fafaf9" } }
{ id: "s-b", dur: 4.9, transition: { type: "iris", at: "70% 40%" } }   // 圆形从 (70%, 40%) 展开
```

方向 `dir`：`left` = 内容往左走（新场景从右边进来），`right`、`up`、`down` 同理。

## 选择表

| 前后两个场景的关系 | 用这个 | 时长 |
|---|---|---|
| 同一主题、背景相近（深→深 或 浅→浅），默认情况 | `crossfade` | 0.5s |
| 深 ↔ 浅切换 | `fadeThrough`（color 用新场景的背景色，或 `#000`） | 0.8s |
| 进入一个新段落、强调「下一章」 | `fadeThrough` 或 `wipe-right` | 0.7–0.8s |
| 同类内容连续翻页（第 1 页 → 第 2 页） | `push-left` | 0.7s |
| 新内容「盖」在旧内容上（详情页、结尾卡片） | `slideOver-up` | 0.7s |
| 金句、重音、高潮开始（必须配音乐重音） | `flash` | 0.36s |
| 从概览「钻进」细节，或节奏加速 | `zoom` | 0.6s |
| 梦幻、回忆、柔和的情绪片 | `blur` | 0.6s |
| 聚焦到某个点展开（Logo、按钮所在的位置） | `iris`（`at` 设成那个点） | 0.8s |
| 快节奏卡点、蒙太奇 | `cut` | 0 |

全片规则：
- 一部片子用 **2–4 种**转场。一种「默认转场」占大多数，另外一两种用在段落切换和高潮。
- `flash` 全片最多 2–3 次，而且要和音乐的 impact 重合。
- 相邻两次转场不要都用「大动作」转场（push / zoom / flash / wipe），中间夹一个 crossfade 或 fadeThrough 让观众喘口气。

## 每种转场的细节

| 转场 | 旧场景 A 做什么 | 新场景 B 做什么 | 缓动 | 适合 / 不适合 |
|---|---|---|---|---|
| `cut` | 分界点瞬间消失 | 分界点瞬间出现 | — | 卡点快剪 / 慢节奏 |
| `crossfade` | 不动 | 透明度 0→1，盖在 A 上 | inOut | 背景相近 / **深浅切换（中间会发灰）** |
| `fadeThrough` | 前半段被色层盖住 | 后半段从色层下露出 | 线性 | 深浅切换、换段落 / 快节奏 |
| `flash` | 同 fadeThrough，色层是强调色，只有 0.36s | 同左 | 线性 | 重音 / 频繁使用 |
| `push` | 整体移出画面 | 整体从反方向移入 | inOut | 同类翻页 / 内容毫无关联时 |
| `slideOver` | 原地缩小到 0.94、变暗 | 从边缘滑入盖住 A | inOut | 叠加新层、结尾卡片 |
| `wipe` | 不动 | 被一条带强调色光条的直线擦出来 | inOut | 新段落、对比（前后对照） |
| `zoom` | 放大到 1.35、模糊、淡出 | 从 1.15 缩回 1、淡入 | inOut | 钻进细节、加速 |
| `blur` | 模糊、淡出 | 从模糊变清晰、淡入 | inOut | 柔和情绪 |
| `iris` | 不动 | 圆形从某点展开 | inOut | 聚焦某个点 |

## 新场景的元素什么时候进场（最重要）

转场分两类，元素进场的时刻完全不同：

### A 类：原地转场 —— crossfade、fadeThrough、flash、zoom、blur、cut

新场景是「原地浮现」的。元素在分界点附近开始入场，看起来是自然的接力：

```js
render(lt, s) {
  M.enter($("#title"), lt, 0.1, "rise");     // 分界点后 0.1s
  M.enter($("#sub"), lt, 0.35, "rise");
  M.stagger($$(".card"), lt, 0.6, 0.1, { preset: "pop" });
}
```

- `fadeThrough` / `flash`：前半段新场景完全不可见，第一个元素最早从 `lt = 0` 开始。
- `crossfade` / `zoom` / `blur`：新场景在前半段已经半透明可见，主体（大标题、主图）可以从 `s.inStart` 开始，跟着场景一起浮现，更连贯。

### B 类：空间转场 —— push、slideOver、wipe、iris

新场景是**整体被搬进来**的，转场开始时它就已经部分出现在画面上了。如果元素等到 `lt = 0` 之后才入场，观众会看到**一块空背景滑进来，然后东西才冒出来**，这是最常见的廉价感来源（见下文「空场景」）。

正确做法：**主体内容从 `s.inStart` 起就在**，只让次要细节在滑入途中或之后再动。

```js
render(lt, s) {
  M.enter($("#title"), lt, s.inStart, "none");                       // 标题跟着场景一起滑进来
  M.enter($("#hero"), lt, s.inStart, "none");                        // 主图也是
  M.stagger($$(".card"), lt, s.inStart + 0.2, 0.12, { preset: "pop" }); // 卡片在滑入途中弹出
  M.countUp($("#num"), lt, 0.2, 1.3, 0, 12800);                      // 数字到位后再滚
}
```

`M.cycle` 轮播放在 B 类转场后时，`start` 也传 `s.inStart`。

## 常见错误与正确写法

| 现象（在 check.png 里看到的） | 原因 | 改法 |
|---|---|---|
| push/wipe 的 50%、75% 帧里新场景是空的 | B 类转场，元素从 `lt=0` 之后才入场 | 主体改为 `M.enter(el, lt, s.inStart, "none")` |
| 深 → 浅 crossfade 的 50% 帧是一片脏灰 | 深浅叠加的平均色 | 改用 `fadeThrough`，color 用新场景背景色 |
| 转场时某个元素突然跳了位置 | 元素原来的 CSS transform 被动画覆盖 | 用 flex 居中；或加 `extra: { yp: -50 }` 补回 |
| 静止帧里元素还半透明 / 模糊 | 入场时刻太晚，或场景太短 | 入场提前；场景加长；保证 `s.outStart - 1.0` 前入场完 |
| 离开时元素先自己消失，然后才转场 | 给元素写了 `out` 退场 | 删掉 `out`，让转场整体带走 |
| zoom 时新场景四周露出旧场景的边 | 自己写了 scale < 1 的入场 | 用库自带的 zoom；需要缩放入场时让 scale 从 >1 缩回 1 |
| 整片转场五花八门 | 每个场景都换一种 | 限制在 2–4 种，按选择表来 |
| flash 闪了但没有冲击力 | 没配音乐重音，或者用得太频繁 | 在 cues 的 hits 里放 impact，同一时刻；全片 ≤ 3 次 |
| 转场太快，像画面跳了一下 | 转场时长 < 0.3s（flash 除外） | 用默认时长 |
| 转场太慢，拖沓 | 转场时长 > 1s | 用默认时长 |
| 两个场景之间露出黑屏 | 没用 timeline，自己算的显隐时间有缝 | 用 `M.timeline`，它保证前后场景重叠 |

## 不用 timeline 时的场景内转场

同一个场景里的内容替换（轮播、步骤）用 `M.cycle`，它会自动让上一组退场、下一组入场：

```js
const step = s.dur / 3;
M.cycle([[...itemA.children], [...itemB.children], [...itemC.children]], lt, s.inStart, step, { preset: "rise" });
```

- 退场在下一组入场前 0.35s 开始，向上淡出；下一组从下方浮入。方向一致，读起来像「往上翻」。
- 左文右图时，文字和图分别调用一次 `M.cycle`；图的 `start` 提前 0.1s，图先到、字后到。
- 最后一组默认不退场，交给场景转场带走。

## 共享元素（常驻元素）过渡

有些元素要跨场景连续存在，比如开场居中的 Logo 缩到左上角一直保留。这类元素不放在任何 section 里，放在所有 section 之后，在总的 `render(t)` 里用全局时间 `t` 控制：

```js
function render(t) {
  tl.render(t);
  const a = tl.at("s-window");   // 第二个场景的分界点
  M.tween($("#logo"), t, a - 0.4, 0.8,
    { x: 0, y: 0, s: 1 },        // 开场：居中、原大
    { x: -820, y: -440, s: 0.3 } // 之后：左上角、缩小
  );
}
```

这比让两个场景各放一个 Logo 再交叉淡化要连贯得多。
