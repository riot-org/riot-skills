## 声音的优先级

有旁白时：**旁白 > 音效 > 音乐**。音乐在旁白下压低 10–15 dB（ducking）。
没旁白时：音乐承担情绪和节奏，重音对准画面的关键时刻。
平台默认静音时（竖屏短视频）：声音是加分项，信息不能只靠声音。

## 用户自带音乐

- 先确认授权。不要从网上下载未授权的音乐来用。
- 找节拍：问用户 BPM，或者看波形找鼓点（`showwavespic`，见下文），或用 `ebur128` / `astats` 按时间看能量峰值。
- 画面迁就音乐：把镜头切换放在小节或拍子上，高潮镜头对齐副歌，结尾对齐乐句结束。
- 音乐比视频长：在乐句结尾处剪，最后 1.5–3 秒淡出；不要在一个音的中间截断。

## 合成配乐（music.cjs）

```bash
node "${SKILL_DIR}/scripts/music.cjs" cues.json music.wav
```

纯代码合成，结果可复现，没有版权问题。音色是一套电子乐：底鼓、拍手、镲片、贝斯、和声铺底、琶音、混响、重音、渐强噪声、点击声、提示音。

cue 文件字段：

| 字段 | 说明 |
|---|---|
| `duration` | 总时长（秒） |
| `bar` | 一小节的长度（秒），BPM = 240 / bar |
| `anchor` | 某个强拍的时刻，用来对齐网格 |
| `progression` | 和弦循环，按小节轮换，如 `["Am","F","C","G"]` |
| `endChord` | 结尾停留的和弦 |
| `sections` | `[{from,to,style}]`，style 见下表 |
| `hits` | `[{t,type,gain}]`：`impact` 低频冲击、`crash` 镲、`click` 点击、`chime` 提示音；`{type:"riser",from,to}` 渐强 |

段落风格：

| style | 内容 | 适合 |
|---|---|---|
| `intro` | 铺底 + 轻琶音，无鼓 | 开场、Logo |
| `groove` | 四拍底鼓 + 反拍镲 + 贝斯 | 铺垫、介绍 |
| `break` | 抽掉鼓，最后一小节滚奏渐强 | 金句、转折前的蓄力 |
| `drop` | 全编制，十六分镲 | 高潮、功能轮播、快剪 |
| `calm` | 半速，声音收暗 | 讲道理、信任、温情 |
| `outro` | 回到主和弦渐弱 | 结尾 |

情绪对照：

| 情绪 | 速度（bar） | 和弦 | 段落 |
|---|---|---|---|
| 科技、产品、有冲劲 | 2.2–2.5s（96–110 BPM） | `Am F C G` | intro → groove → break → drop → outro |
| 温暖、回顾、品牌故事 | 2.8–3.4s（70–85 BPM） | `C G Am F` 或 `F C G Am` | intro → calm → outro，不用 drop |
| 紧张、倒计时、发布 | 1.9–2.1s（115–125 BPM） | `Am Am F G` | groove → break → drop 拉长 |
| 轻松、生活方式 | 2.4–2.6s | `C Am F G` | intro → groove → outro |

示例：`assets/cues.promo.json`（48 秒产品宣传，有冲劲）、`assets/cues.calm.json`（30 秒温暖回顾）。`new.sh` 会把它们复制进工程。

### 从画面时间轴写 cues（一步步来）

1. `node render.cjs video.html --timeline`，得到每个场景的分界点和每个转场的时刻。
2. `duration` = 总时长；`bar` = 时间轴里的 `opts.bar`；`anchor` = 任意一个分界点（比如最规律那段的第一个场景）。
3. `sections`：按场景的分界点切段。开场场景 → `intro`；铺垫 → `groove`；金句前的一个场景 → `break`；功能轮播、快剪 → `drop`；讲信任、温情的 → `calm`；最后一个场景 → `outro`。相邻段首尾时间必须相接。
4. `hits`：
   - 每个 `flash` 转场的分界点 → `impact`（gain 1）；
   - 开场大字（`slam`）的入场时刻 → `impact`（gain 0.7）；
   - 进入 `drop` 段的分界点 → `crash`，前一小节放 `riser`；
   - 光标点击时刻 → `click`；操作成功 → `chime`；
   - 结尾 Logo 入场时刻 → `impact`（0.85）+ `crash`（0.6）。
5. 生成后画波形图，确认尖峰和这些时刻对得上。

想要别的音色（钢琴、弦乐、吉他、人声），合成器做不好；告诉用户这一点，建议他们提供授权音乐。

## 卡点

- **选小节长度**：画面里最常见的切换间隔 = 一小节（或半小节）。例如功能轮播 2.45 秒一项 → bar = 2.45（≈98 BPM），每次切换都在强拍上。
- **anchor**：设成那段轮播开始的时刻。
- **网格外的重音**：大字砸下、闪屏、Logo 落定、点击，不在网格上也没关系，用 `hits` 单独打。
- **蓄力和释放**：重要镜头前一小节放 `riser`，或用 `break` 抽掉鼓，镜头出现时 `crash` / `impact` 加鼓回来。
- **反过来也行**：先定音乐，再按小节时间调画面的时间轴。

## 旁白

- 先写稿，按 4–5 字/秒（中文）或 2.5 词/秒（英文）估时长，再定画面。
- 有真人录音最好。其次是装好的语音合成技能（技能列表里有 TTS / 配音类的，比如 moss-tts）：音色和语速远好于系统自带的，按那个技能的说明合成。它要的 API key 用 `RequestEnv` 向用户要，**不要让用户把 key 贴进对话**，也不要写进脚本或文件。
- 都没有时，用 macOS TTS 做占位（音质一般，要告诉用户）：
  ```bash
  say -v "Tingting" -r 200 -o vo.aiff "第一句旁白。"     # 中文；用 say -v '?' | grep zh_ 查可用音色
  say -v "Samantha" -o vo.aiff "English narration."
  ```
- 一句一个文件，记下每句时长（`ffprobe`），在时间轴上排好位置，再用 `adelay` + `amix` 拼起来（见 ffmpeg-recipes）。字幕的起止直接用这份时长算（每句开始 -0.1s、结束 +0.2s），别凭感觉估。
- 换音色、换语速要先给用户试听：同一句合成两三个版本，用 `![](路径)` 放进回复（Riot 会内嵌播放器），让用户选定再整段合成。
- 旁白和音乐混音时用侧链压缩，让音乐自动给旁白让路。

## 字幕

- 有旁白就一定加字幕；竖屏平台没旁白也要有画面文字。
- **一句旁白一条字幕，放得下就一行。** 1920 宽、40px 字号时一行能放约 24 个汉字（模板 `#captions span` 的 `max-width: 24em`）；竖屏 1080 宽约 18 个。
- **文本里不要手写 `<br>`。** 换行交给 CSS：模板的 `text-wrap: balance` 会在需要时自动折成长短均匀的两行。手写断行会把本来一行放得下的句子硬拆成两行，改了字号、比例后断点也不对了。
- 一句长到两行还放不下，就拆成两条字幕（按意群断开，各自对齐各自那半句旁白），而不是挤成三行。
- 两种做法：
  - **画进 HTML**：`M.captions(box, t, list)`，时间用 `tl.at("s-xxx") + 秒数` 写，场景时长改了也不会错位。推荐。
  - **SRT 烧录或封装**：配方见 ffmpeg-recipes；封装（软字幕）可以让用户在播放器里关掉。
- 字幕时间跟旁白对齐，提前 0.1s 出现，延后 0.2s 消失。

## 响度标准

| 用途 | 目标 |
|---|---|
| 网络视频、社交平台 | 整体 -14 LUFS，真峰值 ≤ -1 dBTP |
| 带旁白的讲解 | -16 LUFS，旁白清晰，音乐比旁白低 10–15 dB |
| 广播电视 | -23 LUFS（EBU R128） |

统一响度用 `loudnorm`（配方见 ffmpeg-recipes），推荐两遍法，更准。

## 不靠耳朵的检查

你听不到声音，所以用测量代替，并且交付时如实告诉用户「数据正常，但听感需要你确认」。

```bash
# 整体响度（LUFS）和真峰值
ffmpeg -i music.wav -af ebur128=peak=true -f null - 2>&1 | tail -12
# 分段响度：开场、结尾应明显轻于主体
ffmpeg -ss 18 -to 38 -i music.wav -af volumedetect -f null /dev/null
# 倍频程频谱（注意 width_type=o，默认是 Q 值）：从 60Hz 往上每倍频程降 3–5 dB 算均衡
for f in 60 125 250 500 1000 2000 4000 8000; do
  ffmpeg -i music.wav -af "bandpass=f=$f:width_type=o:w=1,volumedetect" -f null /dev/null 2>&1 | grep mean_volume
done
# 波形图：看重音位置和段落起伏是否和画面对得上
ffmpeg -i music.wav -lavfi "showwavespic=s=1600x300:colors=#c83e29" -frames:v 1 wave.png
```

要查的问题：
- 有没有削波（峰值贴着 0 dB）；
- 段落之间有没有起伏（全程同一个响度会很累）；
- 低频是不是太重（60Hz 比 1kHz 高 20 dB 以上就偏闷）；
- 重音的时间点是不是落在画面关键帧上（把波形图和时间码对照着看）。
